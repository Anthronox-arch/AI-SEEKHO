## Class 1 — Key Learnings

### 1. Use AI as a Tool, Not a Crutch

AI is a powerful assistant — but it is not a replacement for thinking. If you generate code without understanding it, you become a liability to your team and your project. Always stay engaged, question the output, and learn from what AI produces.

### 2. Basic Domain Knowledge Is Essential

You must understand the code AI generates. Without foundational domain knowledge, you cannot review, fix, or extend that code. AI accelerates your work — it does not remove the need to know what you are building.

### 3. Four Components of Prompt Creation

Every effective prompt should include:

| Component | Purpose |
|-----------|---------|
| **Role** | Define who the AI should act as (e.g., senior developer, code reviewer) |
| **Context** | Provide background — project details, constraints, existing code |
| **Main** | State the core task or question clearly |
| **Conclusion** | Specify the expected output format or end goal |

### 4. Context Is King

Good, clear context is non-negotiable. The quality of context directly determines the quality of AI output — and that translates into cleaner code and easier debugging. Vague prompts produce vague, fragile code.

### 5. Never Compromise on Code Structure

Poor structure leads to code that keeps breaking. Even when AI generates code quickly, always enforce consistent structure — naming conventions, folder organization, and logical flow matter.

### 6. Modularity

Write code in modules. Modular code is:

- Easier to debug
- Easier to test
- Easier to reuse
- Less redundant

Break problems into small, focused pieces instead of one large, tangled block.
